Figure~\ref{fig:seqlen_memory_appendix} shows that peak memory grows with sequence length across all backends, but the gap between FlashSVD and the baselines widens substantially.
At sequence length 128, all backends are relatively close; by length 512, \texttt{flashsvd15} achieves a 65\% reduction over the naive baseline---a gap that does not exist at short lengths.
This divergence reflects the quadratic growth of attention buffers: \texttt{naive} and \texttt{sdpa} both materialize intermediate activations whose size scales as $O(\text{seq}^2 \times \text{heads})$, while FlashSVD eliminates these buffers through fused kernel computation.
The near-identical curves for \texttt{flashsvd} and \texttt{flashsvd15} confirm that both share the same memory-efficient attention path, with \texttt{flashsvd15} trading a marginal 2~MB for substantially higher throughput.

Figure~\ref{fig:seqlen_tput_appendix} shows that \texttt{flashsvd15} achieves 2.33$\times$ the throughput of the \texttt{naive} baseline at sequence length 512, overtaking \texttt{sdpa} at longer sequence lengths.

\texttt{flashsvd} remains below \texttt{sdpa} in throughput at all sequence lengths, consistent with the design tradeoff: \texttt{flashsvd} prioritizes memory savings, whereas \texttt{flashsvd15} improves both memory efficiency and throughput.
The growing throughput gap between \texttt{flashsvd15} and the naive baseline as sequence length increases suggests that the fused kernel's compute-bound behavior scales more favorably than the memory-bandwidth-bound naive path.

\texttt{sdpa} also shows increasing relative savings (from ${\approx}$8\% at length 128 to ${\approx}$38\% at length 512), but FlashSVD maintains a substantially larger advantage throughout, corresponding to the additional rank-expansion buffers that FlashSVD eliminates.

\subsection{Memory and FLOP analysis}

\begin{figure}[t]
    \centering
    \includegraphics[width=0.92\linewidth]{figures/encoders/memory_analysis/memory_breakdown.png}
    \caption{
    Memory breakdown into parameter storage and activation-related overhead for dense and compressed encoder inference.
    Results are shown at bf16, sequence length 512, and batch size 32.
    The figure illustrates how compression reduces parameter memory, while fused backends further reduce total peak memory by lowering activation and buffer overhead.
    }
    \label{fig:memory_breakdown_appendix}
\end{figure}

Figure~\ref{fig:memory_breakdown_appendix} reveals why compression alone does not reduce inference memory.
Low-rank compression cuts parameter storage by 37\% (from 209~MB to 132~MB), but the naive low-rank backend more than triples activation and buffer overhead---from 295~MB (dense) to 875~MB (SVD naive)---because materializing the rank-expanded intermediate tensors requires substantially larger intermediate buffers than standard dense attention.
The result is that SVD with the naive backend uses 1007~MB, double the dense baseline of 504~MB.
\texttt{sdpa} mitigates this by reducing activations to 491~MB (total 623~MB), and FlashSVD brings activations down to 227~MB, pushing total peak memory to 359~MB---29\% below the dense model.
This breakdown indicates that the dominant memory cost at inference time is attention-related buffers, not parameters, and that only a fused kernel can bring total peak memory below the dense baseline.

\begin{figure}[t]
    \centering
    \includegraphics[width=0.78\linewidth]{figures/encoders/memory_analysis/flops_breakdown.png}
    \caption{
    FLOPs breakdown for representative compressed methods on MNLI.
    Results are shown at bf16 and sequence length 512.
    The figure separates effective or useful compute from rank-alignment overhead, highlighting that heterogeneous-rank methods such as AdaSVD can reduce padding-related waste.
    }
    \label{fig:flops_breakdown_appendix}
\end{figure}

Figure~\ref{fig:flops_breakdown_appendix} shows that Triton's \texttt{next\_pow2} rank padding introduces a rank-alignment overhead of 13.3\% for all three uniform-rank methods (SVD, FWSVD, DRONE), because their single shared rank must be rounded up to a power of two for every head.
AdaSVD, which assigns different ranks to different heads based on adaptive rank selection, reduces this overhead to 4.1\%---a three-fold improvement---because the average rounding waste across its heterogeneous per-head ranks is much smaller.
This provides a secondary efficiency gain from heterogeneous-rank compression beyond its primary benefit of allocating fewer total parameters: adaptive ranks not only reduce the total rank budget but also align it more naturally with the kernel's power-of-two constraints, recovering ${\approx}$9 percentage points of otherwise wasted compute.

\begin{figure}[t]

    }

Figure~\ref{fig:kernel_mem_appendix} presents a five-bar progression---Dense (504~MB), Naive (1007~MB), \texttt{sdpa} (623~MB), \texttt{flashsvd} (360~MB), \texttt{flashsvd15} (362~MB)---in which each step in the execution hierarchy delivers a distinct memory reduction.
Naive low-rank inference uses 100\% more memory than the dense model, because materializing the non-fused rank-expansion intermediates for all attention heads is more expensive than standard dense attention.
\texttt{sdpa} reduces peak memory by 38\% relative to the naive backend by eliminating the explicit attention matrix, and FlashSVD then eliminates a further 42\% relative to \texttt{sdpa} by fusing the low-rank projection into a single Triton kernel, bringing total peak memory to 29\% below the dense baseline.
This cascade quantifies the complementary contributions of attention matrix elimination (\texttt{sdpa}) and rank-expansion buffer elimination (FlashSVD) to the overall memory saving.

    The figure illustrates how fused kernels shift time away from generic operations and improve effective execution efficiency.
    }

\end{figure}

Figure~\ref{fig:kernel_tput_appendix} shows that throughput follows a different ordering than memory: the highest-throughput backend is \texttt{flashsvd15} (1471~samples/s), which exceeds even the dense \texttt{sdpa} baseline (1304~samples/s, $+13\%$) by routing computation through a fused Triton kernel that avoids the overhead of separate GEMM launches for each low-rank factor.
\texttt{sdpa} delivers 1203~samples/s, while \texttt{flashsvd} reaches 724~samples/s, reflecting the stronger emphasis of \texttt{flashsvd} on memory reduction than on raw throughput.
That \texttt{flashsvd15} surpasses dense inference throughput---despite operating on a low-rank decomposition that introduces extra matrix multiplications---suggests that kernel fusion can more than offset the additional compute cost of the low-rank factorization in this setting.

Figure~\ref{fig:kernel_diversity_appendix} shows the kernel time breakdown: under the naive backend, cuBLAS/CUTLASS GEMM operations account for approximately 73\% of GPU time, leaving the execution heavily dependent on generic BLAS kernels.
