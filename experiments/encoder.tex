\subsubsection{Memory breakdown and scaling behavior}

To better understand where the memory gains come from, we decompose peak inference memory into parameter storage and activation-related overhead.
Figure~\ref{fig:memory_breakdown_main} shows that low-rank compression reduces parameter memory, but the naive low-rank backend still suffers from large activation and buffer overhead.
In contrast, FlashSVD eliminates most of this overhead, which is why the total peak memory can fall even below the dense baseline.

We further study whether these gains persist under larger workloads.
Figure~\ref{fig:seqlen_scaling_main} shows sequence-length scaling, and Figure~\ref{fig:batch_scaling_main} shows batch-size scaling.
Across both dimensions, FlashSVD v1.5 maintains the best throughput while preserving the memory advantage of fused low-rank execution, indicating that its benefits are not limited to a single operating point.

\subsubsection{Kernel-level analysis}

To better understand the efficiency differences, we inspect kernel-level execution on MNLI.
Table~\ref{tab:kernel_profile_mnli} shows that fused FlashSVD backends reduce execution diversity and simplify the kernel mix relative to the naive path.
This effect is especially clear for AdaSVD under \texttt{flashsvd15}, which exhibits fewer kernel calls, fewer GEMM variants, and lower fragmentation.
Figure~\ref{fig:kernel_breakdown_main} complements this view by showing that heterogeneous-rank compression increases kernel diversity in the naive path, while FlashSVD backends consolidate dispatch and shift a substantial fraction of runtime into fused execution.
